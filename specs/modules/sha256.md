# Module `lib/sha256.bend`

SHA-256 as specified in FIPS 180-4.

## API

| Function | Contract |
|---|---|
| `Sha256/digest(xs) -> List(u24)` | 32-byte SHA-256 digest of `xs` (`len(xs) < 2^24`). |

## Representation

- A 32-bit word is two 16-bit halves `hi, lo` (rule P-2).
- The hash state `H0..H7` is a flat 16-tuple `(ah, al, bh, bl, ..., hh, hl)`.
- The round constants `Sha256/K` are a flat list `[hi, lo, hi, lo, ...]` of
  128 halves; `Sha256/H0` is the initial state.

## Algorithm

1. `Sha256/process(st, xs, total)` splits the input into 64-byte blocks with
   `Sha256/split64(xs, 0) -> (block, rest, count)`. Each step first waits for
   the chaining state: it branches on `Sha256/ready(st)`, which is `ah >> 16`
   (always 0 because halves are below 2^16, but only known once `ah` is), so
   the next block is split and compressed only after the previous compression
   has produced its state (rule P-23). Each full block is compressed; the
   last partial block (0..63 bytes) is padded by
   `Sha256/padding(tail, tail_len, total)`: `0x80`, then zeros up to 56 mod
   64, then the message length in bits as a 64-bit big-endian integer
   (`total < 2^24` bytes, so only the low 4 bytes can be non-zero). The padded
   tail is one block when `tail_len < 56` and two blocks otherwise.
2. `Sha256/compress(st, block)`:
   - `Sha256/block_words` converts the 64 bytes into 32 halves.
   - `Sha256/schedule(48, w0h, w0l, ..., w15h, w15l)` computes the words
     `W16..W63`. The sliding window of 16 words is passed as 32 arguments;
     each step emits `σ1(W[t-2]) + W[t-7] + σ0(W[t-15]) + W[t-16]` and shifts
     the window. `Sha256/apply(f, xs)` applies the curried function to the 32
     halves of the block.
   - `Sha256/rounds(ah, al, ..., hh, hl, ks, ws)` runs the 64 rounds,
     consuming two halves of `K` and two halves of `W` per round, and returns
     the new 16-tuple.
   - The result is added to the input state, half by half with carries.
3. `Sha256/state_bytes` serializes the 8 words big-endian (`W32/to_bytes`).

The σ/Σ functions are expanded inline: a right rotation by `n < 16` of
`(h, l)` is `((h >> n) | (l << (16 - n)), (l >> n) | (h << (16 - n)))`, a
rotation by `n ≥ 16` swaps the halves first, and a right shift by `n < 16`
is `(h >> n, (l >> n) | (h << (16 - n)))`; every result is masked with
`0xFFFF`.

## Cost

About 41 000 HVM interactions per 64-byte block (see
[13-performance.md](../13-performance.md)). Because blocks are processed one
at a time, memory does not depend on the input length beyond the input list
itself. Without the `Sha256/ready` gate, HVM split the whole input ahead of
the compressions and unfolded the 64 rounds of every block while they waited
for the state, about 12 000 nodes per block (192 per input byte): hashing the
signed ranges of a 1.3 MB document needed 248 M nodes, almost the whole
default node buffer.

## Tests

`sha256_0`, `sha256_3`, `sha256_55`, `sha256_56`, `sha256_63`, `sha256_64`,
`sha256_119`, `sha256_1000`: lengths around every padding boundary, inputs
with bytes `>= 0x80`, expected values from an independent implementation
(reproducible with `sha256sum`).
