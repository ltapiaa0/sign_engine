# 12 — Testing

## 1. Unit tests (`test.bend`)

`tests/gen_unit_tests.py` generates `test.bend`. Expected values are computed
in Python (`hashlib`, `zlib`, `base64`, `pow`, `str.encode`), so the Bend code
is checked against independent implementations. Each test is a definition
`t<i>(z)` returning `1` on success; `run(z)` returns
`(number_of_tests, [names of failing tests])`. All constants are built through
the runtime argument `z` (rule P-8).

```sh
python3 tests/gen_unit_tests.py
bend run-rs test.bend        # expected: Result: (N, [])
bend run-c test.bend         # same result on the multi-threaded C runtime
scripts/build.sh test.bend && build/test   # same result on the patched runtime (prints @List/Nil for [])
```

| Area | Tests |
|---|---|
| bytes | `hex`, `hex_decode`, `base64_enc_*`, `base64_dec_*`, `find`, `rfind`, `find_overlap`, `rfind_overlap`, `find_empty`, `find_none`, `split`, `strip_prefix`, `decimal`, `parse_u24`, `from_io`, `sort` |
| text | `text_utf8_roundtrip`, `text_utf16_decode` |

| bigint | `bigint_add`, `bigint_sub`, `bigint_mul`, `bigint_mod`, `bigint_modexp`, `bigint_to_bytes` |

## 2. Fixtures (`tests/fixtures/`)

Generated by `tests/make_fixtures.py` (reportlab, pikepdf and a hand-written
writer):

| Fixture | Structure |
|---|---|
| `classic.pdf` | Two pages, classic xref table, FlateDecode content streams. |
| `objstm.pdf` | Cross-reference stream with PNG predictor, objects in compressed object streams. |
| `linear.pdf` | Linearized file: first-page xref section plus main xref section, hint stream. |
| `forms.pdf` | Indirect `/AcroForm` with an indirect `/Fields` array, a text field, indirect `/Annots` array with a widget and a link annotation. |
| `hybrid.pdf` | Hybrid-reference file: the catalog and the page tree live in an object stream that only the `/XRefStm` cross-reference stream lists; the classic table omits them. |

## 3. End-to-end tests (`tests/e2e.sh`)

1. Builds `build/sign` if needed and creates a temporary key and self-signed
   certificate with OpenSSL (`KEY_BITS`, default 1024).
2. Signs every fixture once, then signs the results of `classic`, `forms`,
   `hybrid` and `objstm` a second time, and `classic` a third time (an input
   above 32 KiB, which exercises the runtime patch of
   [01-architecture.md](01-architecture.md#5-runtime-and-build)).
3. Certifies `classic` with pyHanko (`tests/certify.py`) at DocMDP level 2 and
   signs it (both signatures must validate, `docmdp_ok` true), and at level 1
   (signing must fail with "does not allow changes").
4. Uses a certificate file with the private key appended (must fail with
   "must not contain a private key").
5. With `LARGE=1`, signs a generated 60-page, 640 KB PDF (`LARGE_PAGES`
   changes the page count: 300 pages give 3.2 MB and 750 pages 8 MB, the
   sizes measured in [13-performance.md](13-performance.md)).
6. Validates every output with `tests/validate.py`.

`tests/validate.py <pdf> <root.pem> [--no-trust] [--allow-hybrid]` passes
only if:

- pikepdf opens the file;
- pyHanko (strict mode) reports every signature `intact` and `valid`, and
  `trusted` unless `--no-trust` (used for RSA-1024, which pyHanko's policy
  rejects);
- every signature's modification level is `NONE`, `LTA_UPDATES` or
  `FORM_FILLING` (FR-3) and no certification signature reports
  `docmdp_ok = False` (FR-12);
- `pdfsig`, when installed, reports every signature as valid.

pyHanko reads files in strict mode, which refuses to validate signatures in
hybrid-reference files at all (hybrid cross-reference data is a known vector
for "shadow" attacks on signatures). `--allow-hybrid` switches the reader to
non-strict mode; `tests/e2e.sh` uses it only for the `hybrid` fixture.

## 4. Service smoke test

```sh
SIGN_PORT=8765 SIGN_KEY=key.pem SIGN_CERT=cert.pem SIGN_API_TOKEN=secret python3 service/server.py &
J='Content-Type: application/json'; A='Authorization: Bearer secret'
curl -s localhost:8765/health
curl -s -X POST localhost:8765/api/v1/sign -H "$J" -d '{}'                              # 401
curl -s -H 'Host: evil.example:8765' localhost:8765/health                               # 403
curl -s -X POST localhost:8765/api/v1/jobs -H "$J" -H "$A" -H 'Origin: http://evil.example' -d '{}'   # 403
curl -s -X POST localhost:8765/api/v1/jobs -H 'Content-Type: text/plain' -H "$A" -d '{}'    # 415
curl -s -X POST localhost:8765/api/v1/sign -H "$J" -H "$A" -d '{x'                      # 400
curl -s -X POST localhost:8765/api/v1/jobs -H "$J" -H "$A" \
     -d "{\"pdf\": \"$(base64 -w0 tests/fixtures/forms.pdf)\", \"location\": \"Ñuñoa\"}"
curl -s localhost:8765/api/v1/jobs/<id> -H "$A"                                           # until done
curl -s localhost:8765/api/v1/jobs/<id>/pdf -H "$A" -o signed.pdf
python3 tests/validate.py signed.pdf cert.pem --no-trust
```

A PDF without `startxref` must produce `422 {"error": "pdf: startxref not
found"}`; more than `SIGN_MAX_QUEUE` simultaneous requests produce `429`; a
`name` sent with the server key is ignored.
