# 12 — Testing

All tests are Bend programs and shell scripts. External tools are used only
as independent validators: OpenSSL (`openssl cms -verify`), poppler's
`pdfsig`, `qpdf --check` (optional) and `curl`.

## 1. Unit tests (`test.bend`)

`test.bend` holds 95 tests. Each test is a definition `test_<name>(z)`
returning `1` on success; `run(z)` lists them as `(name, result)` pairs and
`summary` returns `(number_of_tests, [names of failing tests])`. Constants
are built through the runtime argument `z` (rule P-8).

```sh
bend run-rs test.bend                       # expected: Result: (95, [])
bend run-c test.bend                        # same result on the multi-threaded C runtime
scripts/build.sh test.bend && build/test    # same result on the patched runtime (prints @List/Nil for [])
```

Expected values were computed with independent implementations and are
written in the tests as literals: SHA-256 digests (reproducible with
`sha256sum`), zlib streams (`zlib`), base64 (`base64`), big-integer results,
UTF-8/UTF-16 conversions and dates (`date -u -d @<seconds>`).

| Area | Tests |
|---|---|
| bytes | `hex`, `hex_decode`, `base64_enc_*`, `base64_dec_*`, `base64_strict`, `base64_strict_invalid`, `find`, `rfind`, `find_overlap`, `rfind_overlap`, `find_empty`, `find_none`, `split`, `strip_prefix`, `measure`, `decimal`, `parse_u24`, `from_io`, `sort` |
| text | `text_utf8_roundtrip`, `text_utf16_decode` |

## 2. Fixtures (`tests/fixtures/`)

The fixtures are committed files produced once by third-party writers
(reportlab, pikepdf, pyHanko) so that the reader is tested against PDFs it
did not write. They are test data; regenerating them is not part of the
build.

| Fixture | Structure |
|---|---|
| `classic.pdf` | Two pages, classic xref table, FlateDecode content streams. |
| `objstm.pdf` | Cross-reference stream with PNG predictor, objects in compressed object streams. |
| `linear.pdf` | Linearized file: first-page xref section plus main xref section, hint stream. |
| `forms.pdf` | Indirect `/AcroForm` with an indirect `/Fields` array, a text field, indirect `/Annots` array with a widget and a link annotation. |
| `hybrid.pdf` | Hybrid-reference file: the catalog and the page tree live in an object stream that only the `/XRefStm` cross-reference stream lists; the classic table omits them. |
| `certified/p2.pdf` | `classic.pdf` certified by pyHanko with DocMDP level 2 (`FILL_FORMS`), certificate "sign_engine fixture certifier". |
| `certified/p1.pdf` | The same with DocMDP level 1 (`NO_CHANGES`). |

Large documents are generated by `mkpdf.bend`
([modules/mkpdf.md](modules/mkpdf.md)).

## 3. Validation (`tests/validate.sh <pdf> <root.pem> [--no-trust]`)

Passes only if:

1. `qpdf --check` reports no errors (when `qpdf` is installed);
2. `pdfsig` finds at least one signature and reports every one as
   "Signature is Valid.";
3. the Bend verifier (`build/verify`, [modules/verify.md](modules/verify.md))
   reports every signature as valid: byte-range layout, gap equal to
   `/Contents`, CMS structure and attributes, RSA signature, and only
   signature-related changes after each signed revision (FR-3, FR-12);
4. for every signature, `openssl cms -verify -noverify` verifies the CMS
   extracted by the verifier against the signed byte ranges, and signatures
   made with the certificate `root.pem` also verify with
   `-CAfile root.pem -purpose any` (trust), unless `--no-trust`.

## 4. End-to-end tests (`tests/e2e.sh`)

1. Builds `build/sign`, `build/verify` and `build/mkpdf` if needed and
   creates a key and self-signed certificate with OpenSSL (`KEY_BITS`,
   default 1024).
2. Signs every fixture of `tests/fixtures/` once, then signs the results of
   `classic`, `forms`, `hybrid` and `objstm` a second time, and `classic` a
   third time (an input above 32 KiB, which exercises the runtime patch of
   [01-architecture.md](01-architecture.md#5-runtime-and-build)).
3. Signs `certified/p2.pdf` (both signatures must validate) and
   `certified/p1.pdf` (signing must fail with "does not allow changes").
4. Uses a certificate file with the private key appended (must fail with
   "must not contain a private key").
5. With `LARGE=1`, signs a document generated by `mkpdf` with `LARGE_PAGES`
   pages (default 60).
6. Validates every output with `tests/validate.sh`.

## 5. Service tests (`tests/service.sh`)

Builds `build/server`, starts it with `systemd-socket-activate` on
`127.0.0.1:$PORT` (default 8765) in a temporary directory with its own
`server.conf`, key and jobs directory, and checks with `curl`: health, form,
`401`, foreign `Host` and `Origin` (`403`), `415`, invalid JSON and base64
(`400`), unknown path (`404`), unknown method (`405`), unknown job (`404`),
a document above `max_pdf` sent with `Expect: 100-continue` (`413`), a
document the signer rejects (`422`), synchronous signing as raw PDF (with a
non-ASCII `location`) and as JSON, and a complete job (`202`, `409` while
running, status `done`, download), validating every signed PDF with
`tests/validate.sh` and checking that a client-supplied `name` is ignored
with the server key.
