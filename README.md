# sign_engine

A PDF digital signature engine written in [Bend](https://bend-lang.com/):
reusable Bend libraries (bytes, SHA-256, big integers, RSA, ASN.1/DER, X.509,
CMS, DEFLATE, PDF), a command line signer and an HTTP service that exposes it
to web clients.

Signatures are **PAdES B-B** (`/SubFilter /ETSI.CAdES.detached`, RSA PKCS#1
v1.5, SHA-256) added through an incremental update, and validate in pyHanko
and poppler's `pdfsig`:

```
[Signature12] intact=True valid=True trusted=True coverage=ENTIRE_FILE modification=NONE
pdfsig: 1 valid signature(s)
```

The design is documented in [`specs/`](specs/README.md), which is the source
of truth for behavior; source files intentionally carry no comments.

## Layout

```
lib/          Bend libraries (bytes, text, sha256, bigint, rsa, asn1, x509, cms, inflate, pdf, signer)
sign.bend     command line program
test.bend     unit tests (generated by tests/gen_unit_tests.py)
service/      HTTP API (Python standard library, transport only)
scripts/      build script (Bend -> C -> gcc)
tests/        fixtures, end-to-end tests, validation
specs/        software design specification
```

## Requirements

- `cargo install hvm bend-lang` (tested with bend-lang 0.2.38 and hvm 2.0.22)
- gcc
- Python ≥ 3.9 for the service
- For tests: OpenSSL, `pip install pyhanko pikepdf reportlab`, optionally `pdfsig` (poppler-utils)

## Usage

```sh
scripts/build.sh                          # produces build/sign (patched HVM runtime, see specs/01)

mkdir job && cd job
cp document.pdf input.pdf && cp signer-key.pem key.pem && cp signer-cert.pem cert.pem
printf 'reason=Approval\nlocation=Santiago\ntime=20261023120000\n' > params.txt
../build/sign                             # writes output.pdf, or error.txt on failure
```

HTTP service:

```sh
SIGN_API_TOKEN=change-me SIGN_KEY=/path/key.pem SIGN_CERT=/path/cert.pem python3 service/server.py

curl -s -X POST localhost:8080/api/v1/sign \
  -H 'Authorization: Bearer change-me' \
  -H 'Content-Type: application/json' -H 'Accept: application/pdf' \
  -d "{\"pdf\": \"$(base64 -w0 document.pdf)\", \"reason\": \"Approval\"}" \
  -o signed.pdf
```

See [specs/10-cli.md](specs/10-cli.md) and
[specs/11-http-service.md](specs/11-http-service.md) for the full contracts.

## Tests

```sh
python3 tests/gen_unit_tests.py && bend run-rs test.bend   # expected: (N, [])
scripts/build.sh test.bend && build/test                    # same tests on the patched C runtime
python3 tests/make_fixtures.py                              # regenerates tests/fixtures
tests/e2e.sh                                                # sign + validate every fixture (RSA-1024)
KEY_BITS=2048 tests/e2e.sh                                  # same with RSA-2048 and trust checks
LARGE=1 tests/e2e.sh                                        # also signs a generated 640 KB PDF
LARGE=1 LARGE_PAGES=750 tests/e2e.sh                        # ... or an 8 MB one (about 9 minutes)
```

## Limitations

Unencrypted documents and keys, RSA only, invisible signatures, no
timestamps or long-term validation data; documents certified with DocMDP
level 1 are refused. With RSA-2048, in the development container, a 2 KB
PDF takes about 65 s, a 640 KB PDF about 100 s and an 8 MB PDF about
8.5 minutes; documents up to 8 MiB are accepted by default (`SIGN_MAX_PDF`).
Each signer process can use up to about 4.5 GiB of memory (see
[specs/13-performance.md](specs/13-performance.md)).
